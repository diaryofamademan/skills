# Changing the Game

Part of `game-theory-for-decisions`, version 1.0.0.

Use this reference after you have found the best response inside the current game and the result is still poor. A best response accepts the players, rules, and scope as fixed. A game-changing move alters one of those features.

The core lesson from Brandenburger and Nalebuff is practical. Do not ask only how to win the current game. Ask whether a different game would create more value, reduce dependence, or produce a better division of value.

## Map the Value Net first

The **Value Net** places one focal player in the center and maps four groups around it.

- **Customers** receive the player's product or service and provide payment or other value.
- **Suppliers** provide labor, capital, materials, data, distribution inputs, or other resources.
- **Competitors** make the focal offer less valuable to customers or bid for the same scarce resources.
- **Complementors** make the focal offer more valuable. A complementor may provide an adjacent product, a standard, a channel, content, infrastructure, or trust.

One actor can occupy several roles. A marketplace may be a channel, a rule maker, a competitor, and a data supplier. A large customer may also fund a rival. Record each role separately. A single friendly or hostile label hides the real game.

For each actor, record:

| Field | Question |
| --- | --- |
| Role | Which Value Net roles does this actor fill? |
| Objective | What outcome does the actor seek? |
| Added value | How does total value change when this actor joins? |
| Dependence | How hard is it for others to replace this actor? |
| Evidence | Is the claim `observed`, `declared`, `inferred`, or `unknown`? |
| Likely response | What will this actor do if the game changes? |

Use payoff labels as well. A value estimate may be `measured`, `declared`, `inferred`, or `unknown`. Do not turn a rough value map into a false exact valuation.

## Understand added value

A player's **added value** is the total value created when that player is in the game minus the total value created when that player is out of the game. It is not the same as revenue. It is not the same as profit already captured.

Added value helps explain bargaining power. A player that is hard to replace and creates a large increase in total value has a strong claim. A player that adds little unique value faces more pressure. The actual split still depends on outside options, rules, information, timing, and competition.

Ask three questions:

1. What becomes possible when we join?
2. What remains possible if we leave?
3. Which other player can reproduce our contribution, at what cost and delay?

Do the same analysis for each major counterpart. A negotiation fails when each side sees only its own added value.

## Use PARTS to search for a better game

PARTS names five places to intervene: Players, Added values, Rules, Tactics, and Scope.

### P — Players

Change who participates, who decides, or who enters first.

Possible moves include:

- Add a qualified buyer, supplier, partner, or complementor.
- Remove a gatekeeper by using a direct channel.
- Combine fragmented buyers or suppliers through a lawful structure.
- Split a powerful counterpart's roles across separate negotiations.
- Bring in a certifier, escrow agent, auditor, or platform that changes trust.
- Sequence entry so a proof case exists before a larger player joins.

Every added player changes more than the headcount. The new player needs a payoff, information, and a reason to stay. Model their response before inviting them.

### A — Added values

Raise your added value or reduce a harmful dependence.

Possible moves include:

- Add a capability that the other side cannot easily copy.
- Package complements into a complete outcome.
- Reduce switching costs for customers without trapping them.
- Build a credible outside option.
- Develop a second source for a scarce input.
- Make another player's offer more valuable through integration or distribution.
- Reduce the unique value of a blocking player by supporting a standard or alternative.

Do not claim added value from features the customer does not value. Test willingness to pay, time saved, risk reduced, or revenue enabled. Label the evidence.

### R — Rules

Change the formal or informal rules that govern moves and outcomes.

Possible moves include:

- Set transparent qualification and scoring criteria.
- Change the order of offers, trials, or approvals.
- Add deadlines, review points, or staged decisions.
- Set default renewal, termination, and cure rules.
- Tie payment to verified milestones.
- Limit what information is released at each stage.
- Change voting, veto, or escalation rights.
- Add audit and enforcement provisions.

Rules can improve trust and reduce gamesmanship. Rules can also freeze a weak position. Test the rule from each major player's seat. Use [`mechanisms-and-auctions.md`](mechanisms-and-auctions.md) when the task is to design a complete allocation or bidding mechanism.

### T — Tactics

Tactics shape what players perceive about the game. In this skill, tactics must be truthful. Use evidence, demonstrations, references, transparent process, and real commitments to correct a mistaken perception.

Possible moves include:

- Show a working result instead of claiming one.
- Publish clear criteria that all parties can test against.
- Explain the process and the next decision point.
- Make a limited commitment that is visible and costly to reverse.
- Correct a false belief with source documents.
- Reduce uncertainty with a pilot or guarantee that the firm can honor.

Do not use fake scarcity, false offers, invented deadlines, misleading comparisons, or selective disclosure that creates a materially false impression. Perception work without honesty becomes deception and destroys the repeated game.

Use [`commitments-signals-and-information.md`](commitments-signals-and-information.md) to test whether a tactic sends a real signal or is only cheap talk.

### S — Scope

Change which issues are linked and which games affect each other.

Possible moves include:

- Link two issues when a trade creates value on both sides.
- Separate two issues when linkage creates deadlock.
- Extend a one-time deal into a governed relationship.
- Shorten the term when uncertainty is high.
- Split a large commitment into stages.
- Add a territory, product, customer group, or time period.
- Remove a sensitive issue and settle it under a separate process.
- Exit a game whose best available outcome is still unacceptable.

Scope cuts both ways. Linkage can unlock a trade. Linkage can also let one dispute poison every other issue. State the contagion path before linking games.

## A six-step game-change procedure

1. **Name the defect.** Is the problem weak added value, dependence, a bad rule, a perception error, a blocking player, or harmful linkage?
2. **Set the target.** Name the outcome the new game must make possible.
3. **Generate one move per PARTS letter.** Do not stop at the first idea.
4. **Model responses.** For each move, map the likely gain, loss, and countermove for every major player.
5. **Run legality and repeat checks.** Test competition law, contracts, fiduciary duties, privacy, reputation, and future trust.
6. **Pilot the smallest change.** Prefer a staged test with a review date and a reversal path.

Score options with ranges or ranks. Payoff provenance stays visible. A high-impact move based on `unknown` payoffs should not beat a moderate move based on `measured` payoffs without an explicit risk decision.

## Small generic example

A specialist training firm receives most of its work from one corporate reseller. The reseller controls the client relationship and takes a large share. The firm wants a better split.

The Value Net shows that the reseller is both a channel and a gatekeeper. A software partner is a complementor because its users need the training. Past delivery scores are `measured`. The reseller's claim that clients will not buy direct is `declared`. The firm's belief that some clients prefer direct support is `inferred` from inbound questions.

The firm searches PARTS:

- **Players:** Add the software partner as a referral source.
- **Added values:** Package training with an implementation checklist that raises software adoption.
- **Rules:** Use a written referral fee and direct client consent for each introduction.
- **Tactics:** Show measured completion and adoption results to prospective clients.
- **Scope:** Start with one non-exclusive workshop series instead of renegotiating the whole reseller relationship.

The firm does not threaten the reseller or secretly divert reseller clients. It builds a lawful second channel, raises its added value, and reduces dependence. The reseller may respond with better terms, reduced referrals, or its own package. The firm models all three before acting.

## Decision checklist

- [ ] The best response inside the current game is already known.
- [ ] The specific defect in the current game is named.
- [ ] Every Value Net role is mapped, including dual roles.
- [ ] Added value is estimated for the user and each major counterpart.
- [ ] At least one option is generated for each PARTS letter.
- [ ] New players have a clear reason to join and stay.
- [ ] Rule changes are tested from every major player's seat.
- [ ] Tactics rely on truthful evidence and real commitments.
- [ ] Scope changes name both benefits and contagion risks.
- [ ] Responses, countermoves, and end-game effects are modeled.
- [ ] Evidence and payoff provenance labels are visible.
- [ ] A pilot, owner, review date, and reversal path are set.

## Ethical and legal limits

Do not change the game through collusion, bid rigging, market division, price coordination, bribery, deceptive foreclosure, theft of confidential information, or coercive exclusion. Some alliances, exclusivity terms, information exchanges, and refusals to deal can create competition-law risk. Get legal review before coordinating with competitors, sharing sensitive market information, imposing broad exclusivity, or designing rules for a regulated market.

A better game should create value, improve trust, or reduce waste. It should not merely hide power, mislead a weaker player, or transfer harm to people outside the map.
